# Studio: information reduction pass

September 8, 2026. Implemented in the local Studio static interface.

## Research and decision

The issue was accumulated explanations and duplicated summaries. This pass removes content and simplifies presentation rather than adding another dashboard layer.

[NN/g: Aesthetic and Minimalist Design](https://www.nngroup.com/articles/aesthetic-minimalist-design/) explains that irrelevant and rarely needed information competes with task-critical information. Minimalism means retaining utility while reducing noise; it does not prescribe an empty visual style.

[NN/g: Progressive Disclosure](https://www.nngroup.com/articles/progressive-disclosure/) supports keeping primary tasks visible and revealing secondary detail when needed. This informed the optional analysis, difficulty explanation, connection instructions, product inventory and version documentation disclosures.

[SmoothUI: AI Design Slop](https://smoothui.dev/blog/ai-design-slop) describes repeated card templates and fashionable visual defaults as symptoms of generic generated interfaces. This is practitioner commentary, not proof that a particular interface was generated by AI. The audit uses observable usability problems, not an AI-origin detector.

## Audit taxonomy

| Pattern | Studio finding / action |
| --- | --- |
| Heading, subtitle and helper text saying the same thing | Removed page tagline and launcher introduction; shortened step headings. |
| Repeated assurance and methodology copy | Removed sidebar evidence assurance and inspector footer. Scientific limitations remain in findings; paid scope remains beside the analysis action. |
| Card grids used for comparable records | Outcome cards are now separated rows with status, task, summary and an opening affordance. |
| Summary that duplicates the detail view | Requirement previews removed from overview; full requirements and evidence remain in the inspector. |
| Repeated call-to-action sentence on every item | Removed repeated “Read findings & evidence” footers; rows remain semantic, keyboard-focusable buttons. |
| Charts without a comparison | Model comparison bars appear only with multiple approaches. |
| Zero-value status clutter | Removed zero execution-issue labels and zero hidden-selection messages. Nonzero issues remain visible. |
| Optional work competing with the main journey | Reasoning review is a disclosure with Available, Failed, Running or Optional status. Paid action and budget explanation remain inside it. |
| Persistent tutorial text for familiar actions | Connection and version help is available on demand; editor empty-state instructions are shorter. |
| Full inventory visible during editing | Included products is a disclosure. Field definitions and researcher controls remain immediately available. |
| Technical implementation detail in product copy | Removed disconnected analysis-provider announcement and shortened architecture readiness descriptions. |
| Decorative gradient, glass and icon-card templates | No new decorative treatments introduced. Existing restrained palette retained. |
| Unclear click targets and hover-only controls | Outcome rows retain native buttons, focus outlines and a visible arrow. Help uses native details/summary. |
| Hidden failures under a clean-looking surface | Failure status, launch validation, budget checks, connection recovery and unsaved state retained. |
| Fake metrics or conflated facts and interpretations | No invented metrics; original verdicts, observed evidence and model analysis remain distinct. |
| Disclosure reset during background refresh | Reasoning review retains its open state when its report re-renders. |

This is a practical taxonomy, not an exhaustive scientific catalog of AI-specific mistakes. High information density is appropriate when it supports comparison; repeated or premature information is the target.

## Evidence and maintenance

`artifacts/studio-deslop/before/` preserves the immediate pre-pass static files. `artifacts/studio-deslop/ui-changes.patch` records this pass independently of the preexisting untracked Studio directory. The mobile audit is retained alongside it.

When changing Studio, require each visible explanation to answer a current user question. Prefer one authoritative location for a fact; keep action costs, failures, constraints and recovery visible at the point of decision. Use disclosure for supporting detail, not for concealing essential decisions.

## Task output refinement

Outcome labels now use a shortened first sentence, with full instructions preserved in an expandable section. Findings show a concise verdict; assessment, requirements, unexpected changes, actions and next question expand independently. Action evidence opens in a native modal with paired input/output and an expandable raw event. Expand opens the full output; Back returns from evidence to expanded findings. Closing restores focus without changing the selected result.

Validation: JavaScript syntax passes; 22 existing browser regression checks pass. Focused checks confirm modal opening, paired responses, Back navigation, preserved selection, focus restoration and mobile fit. Evidence must finish streaming before its link resolves; the existing loading message handles early clicks. Mobile expanded-output Lighthouse: 35 audits passed, zero failed, accessibility 100. No paid requests.

## Scientific findings

Task output now places event-cited critical analysis before raw assessment sections. Findings distinguish observations from untested hypotheses and expose limitations and a falsifiable next experiment. Unreviewed attempts explicitly say no mechanism review exists rather than presenting check summaries as analysis. The current expense run received a locally authored six-finding review with provenance, trace hash and exact event references; its original verdict and execution are unchanged. External Gemini dispatch was rejected by automatic approval review; no additional provider request was made. Local review is outcome-visible, unblinded and uncalibrated, stated explicitly in its provenance.

The findings distinguish the scope-check failure, returned-record-ID inconsistency, possible adapter/contract issue, unsupported policy threshold and absent verification read. No controlled replay has yet established causation. Existing analysis safeguards: 25 offline tests pass.
