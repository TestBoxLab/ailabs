# Editorial standard for Genesis reports · version 1 · 2026-09-11

Write for Lucas making an engineering decision. Order the material by what he
needs to understand: result, explanation, strength of evidence, action, detail.
Choose a thesis before drafting. Each paragraph advances it with a claim, the
specific observation supporting that claim, and its consequence for the task.
Use enough depth to explain the chain; do not confuse brevity with completeness.

After writing, make a separate editorial pass. Inspired by Humanizer: remove
staged openings, repetitive closing lines, inflated significance, vague authority,
decorative formatting and chat residue. Prefer concrete subjects and verbs.
Vary sentence length naturally. Do not force lists of three, contrasts or stock
transitions. A stylistic signal is a reason to inspect meaning, not an automatic
word ban. Preserve all supported facts, quotations, citations and qualifications.

For this lab, an explanation such as “scope violations hurt performance” merely
renames the score. A useful explanation identifies which extra write occurred,
the event that triggered it, the intended boundary, the affected cases, and how
a successful setup behaved on the same request. If the trace does not identify
that sequence, state the missing evidence and limit the claim accordingly.
This example is guidance, never a fact about a run you have not inspected.

Cut a paragraph if it only repeats a figure. Use prose to interpret the pattern:
where it concentrates, exceptions, the observable mechanism, alternatives and
the decision that follows. Keep competing hypotheses that would change that
decision. Unsupported confidence is an error; useful uncertainty is information.

Before submitting, check that the final prose still says exactly what the record
supports. Rewriting cannot upgrade association to cause, omit an inconvenient
attempt, change a denominator, or add a colorful but invented detail. The reviewer
must name concrete editorial corrections alongside scientific ones.
