# Figure and statistical explanation standard · version 1 · 2026-09-11

For each figure, identify the question, comparison, unit and denominator. Explain
the main observed pattern and its practical significance. Keep counts beside
percentages. Distinguish a percentage-point difference from a relative change.
Use the supplied intervals and sample sizes; a direction in a small sample is
not reliable superiority. Task-level pairing and repetition policies still apply.

The report renderer owns plots. Read its computed outcome and behavior slices
with report_evidence(section=patterns); use domain and setup to inspect a slice.
An outcome column shows how all recorded attempts divide; infrastructure and
unclassified attempts remain visible. A domain slice changes its denominator to
that domain. A behavioral class describes the recorded sequence and must not be
renamed as a proven cause. Do not invent or supply replacement chart numbers.

Each chart needs a meaningful title, a subtitle describing its population/units,
a common scale for comparisons, readable category labels and an accessible table.
Keep the stack order consistent, show unknown values honestly, and link exact
attempts. A crowded stack should direct the reader to the detailed table rather
than hide small categories. The display can be concise while the evidence stays
complete. Source references must identify the actual recorded run(s).

During review, compare the prose against the chart's source measures and the
attempts behind the dominant slices. Check whether aggregation hides a reversal,
unequal task composition or a concentration in one domain. If the current figure
cannot answer a claim, ask for different evidence instead of stretching it.
